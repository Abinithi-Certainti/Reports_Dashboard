How field mapping works

From an old Power BI report on SQL Server to the new PostgreSQL database. Real example: the Tender Report (19 fields).

The 6 steps

1
Extract

5 read-only queries read the old report: tables, fields, formulas, links, source SQL.

Person · 10 min
2
Save in catalog

Everything goes into the catalog database, one record per report.

Automatic
3
Confirm tables once

Old table → new table. Shared by all reports, so each table is confirmed only once.

Person · once per table
4
Match fields by rule

tools/auto_map.py applies the rules below and checks each field exists in the new database.

Automatic
5
Review leftovers

Only fields marked Review or Missing reach a person. Nothing is guessed.

Person · only leftovers
6
Go live

The report's SQL uses only confirmed new names, and a test runs it against the new tables.

Automatic

The matching rules (tried in order - the first one that finds a real field wins)

Auto1 · Exact

Same name, lower-cased.
Plaza → plaza

Auto2 · Snake case

Split the words, join with "_".
PaymentTypeName → payment_type_name

Review3 · Ignore underscores

Same letters, "_" in different places.
CTLOCATION → ct_location

Missing4 · Nothing found

No field in the new database fits. A person maps it by hand.

Step 6 - the same query, before and after

Old · SQL Server (Power BI)
-- Payment Type Summary SELECT COUNT(a.[OrderID]), SUM(a.[PaymentAmount]), a.[PaymentTypeName], e.LocationName FROM [dbo].[POS_ORDERPAYMENTS] a JOIN nslm e ON a.StoreId = e.StoreID WHERE Endday BETWEEN ... AND ...
New · PostgreSQL (Report Engine)
-- payment_type_summary SELECT count(a.order_id), sum(a.payment_amount), a.payment_type_name, e.location_name FROM master.pos_order_payments a JOIN nslm e ON a.store_id = e.store_id WHERE a.end_day >= ... AND ...
Why tables are confirmed by a person: old table names often break the rule - POS_ORDERPAYMENTS is all capitals, so no rule can tell where the words split. Without confirmed tables the tool marks 15 of 19 fields as Review; with the 4 tables confirmed once, 18 of 19 match automatically. Every later report that uses these tables gets its fields matched automatically too.
